# 技术验证计划

本文定义技术验证的最小样例、预期结果和采用条件。原型功能范围见[技术原型方案](prototype.md)，工程约定见[开发指南](../development.md)。本文描述计划，实际结果在验证后形成。

## 验证组织

文档完成后先进行整体审查，审查结论用于修订验证范围。依赖安装、验证程序和正式实现在审查后安排。验证采用 Windows 工具链，文件与结果整理沿用仓库协作约定。

先验证独立能力，再验证跨模块闭环。每项使用小而完整的样例，记录输入、版本、配置、预期、实际结果与结论。发现错误时保留复现输入并修复原因，能力缺口通过补充实现、调整设计或更换依赖处理。

| 顺序 | 项目 | 预期产出 |
| --- | --- | --- |
| 1 | 地图与几何 | 明确可导入的地图子集及可用的查询接口 |
| 2 | 运动与接触 | 建立可解释的数值案例和误差条件 |
| 3 | 桌面界面 | 确认可构建、可交互的 Windows 原生画布 |
| 4 | Python 通信 | 确认连接、批量状态、控制与生命周期交付 |
| 5 | 原型闭环 | 使用同一场景验证 GUI、headless 和 Python 的一致语义 |

各项采用结论包含功能覆盖、已知限制、构建分发成本和适用范围。具体依赖版本在采用时固定，正式设计同步维护稳定结论，详细过程保存在本地记录中。

## 地图与几何

| 最小样例 | 预期结果与通过条件 |
| --- | --- |
| 一段直路，包含已知长度、宽度和行驶方向 | 导入后几何、车道方向与源身份可追溯；查询点和边界符合样例定义 |
| 弧线、宽度变化和车道连接 | 曲线位置与切向连续，采样误差可测；拓扑能返回实际连接关系 |
| 简单交叉口与横穿区域 | 查询返回真实候选及通行区域；路口多候选保持明确 |
| 中心点、跨线轮廓、道路外位置 | 分别返回位置归属、完整轮廓占用和空归属；保持实际位姿 |
| 不支持的元素或失效引用 | 指出源位置、元素与原因，导入能力范围保持明确 |

采用地图库需要同时满足结构读取、几何求值和拓扑需求。仅成功解析文件不构成通过。先覆盖原型使用的平面道路，再单独安排高程能力。

几何精度通过解析形状或独立参考计算比较。采样间隔、投影容差和边界容差在执行前明确，结果按相应单位报告。

## 运动、接触与轨迹

测试参数用于验证数值关系，现实交通参数通过后续数据校准确定。

| 最小样例 | 预期结果与通过条件 |
| --- | --- |
| 匀速直行与恒加速度 | 位置和速度与解析解一致，误差满足事先声明的绝对及相对容差 |
| 已知初速和减速度的停车 | 停车时间、位移与解析关系一致，剩余区间按停车状态处理 |
| 固定转向角的恒速转弯 | 后轴轨迹半径符合模型关系，公开中心位姿与速度转换正确 |
| 目标转向角阶跃 | 实际转向角按速率上限变化，控制请求和实际状态分别记录 |
| 行人起步、停止和转向 | 实际速度与加速度遵守配置，运动与朝向规则一致 |
| 两主体途中接触 | 定位首次接触，涉事主体停驶占道，其他主体完成相应剩余区间 |
| 持续接触、后续追撞与清除 | 接触身份稳定，新的接触过程独立记录，清除后结束相应占用 |
| 跟踪、滚动替换与轨迹到期 | 实际运动保持约束，反馈包含偏差，替换基于实际状态，到期交还默认行为 |

数值比较从简单输入开始，使用例如 `0.1 s`、`0.05 s` 和 `0.025 s` 的步长检查误差变化。它们是验证条件，生产默认值依据结果确定。时间步、内部子步与接触定位容差分别记录。

解析案例采用可事先计算的误差标准；轨迹跟踪案例先确定空间误差、航向误差与速度误差目标，再运行比较。阈值的依据与适用场景进入验证结论。

## Python 通信与会话

| 最小样例 | 预期结果与通过条件 |
| --- | --- |
| 启动应用及连接已有实例 | 就绪信息、实例身份、协议版本与 endpoint 对应，失败阶段明确 |
| 两个应用与多个客户端 | 实例相互隔离，同一实例的客户端共享世界，来源和回合身份正确 |
| 部分消息、连续消息及较大批次 | 长度分包完整，解码与对象包装正确，消息上限有效 |
| 查询后单步、连续控制与事件回调 | 沿用相同推进机制，固定版本一致，每个必需回合完成一次 |
| 注册修改、取消、暂停和重置 | 实际生效边界与确认一致，既有义务和旧运行失效结果明确 |
| 控制异常、超时及断线 | 该次运行故障停止，保留现场并通知其他客户端 |
| 正常断开、终止及退出 | 影响范围符合设计，等待中的操作收到完成或取消结果 |

批量传输分别记录编解码、传输、Python 对象构造、内存及完整回合耗时。先测小批次，再递增对象数量定位成本。具体规模和时延目标在执行计划中声明，结论包含硬件与数据条件。

## 模型与任务验证

[模型接入与任务](agents/policies.md)定义接入边界，以下样例检验平台语义。参考行为的现实适用性通过独立研究评价。

| 样例 | 预期结果 |
| --- | --- |
| 混合输出层次 | 路线跟随、轨迹和直接控制主体共享同一固定版本，记录各自来源与有效输入 |
| 慢周期策略 | 已提交动作在声明区间内持续执行，到期使用已配置的接续行为；缺失必需输入时报错停止 |
| 目标生命周期 | 到达按实际状态判定，等待保留任务；替换、取消及失败具有独立原因，实体保持明确生命周期 |
| 参数与切换 | 无效参数保留原配置；有效修改在确认边界一次生效；接管结束从实际状态接续 |
| 外部私有状态 | 普通 Python 控制自由持有状态；缺失必要恢复能力时拒绝中途继续决策或分支，并报告所缺条件 |
| 参考行为 | 车辆连续跟随和停车恢复、非机动车独立能力、行人区域到达；安全通过与接触案例均可复查 |

## 闭环与采用结论

最终使用同一条道路与车人交互场景，分别从 GUI、headless 与 Python 驱动。相同配置、随机条件和已确认命令顺序应产生一致的动作、状态与事件。改变显示刷新频率应保持逻辑结果一致。

每项结论区分通过、需要补充和不采用。通过项写明版本及能力范围；需要补充的项目明确缺口和下一步；不采用的项目保留原因并调整依赖方案。实现与领域行为结论分别表达。

本计划的文档审查关注样例是否覆盖关键风险、预期是否可观察、通过条件是否可复查，以及范围是否符合首轮目标。实际测量数据在执行验证后补充。
