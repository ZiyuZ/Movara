# 技术原型方案

本文定义技术原型的场景、参考策略和验收范围。平台阶段目标见[路线图](../ROADMAP.md)，筹备进度见[工程筹备计划](../TODO.md)。

原型场景为一个路段加一个交叉口，使用普通 OpenDRIVE，包含车辆、行人和路中违规横穿。规则或脚本策略用于验证数值与工具流程。

GUI 与 CLI 从原型开始同时交付，共用单个应用，默认启动 GUI，以 `--headless` 进入无界面模式。Python API 库支持连接已有应用，以及自动启动 GUI 或 headless 应用。

早期以单机运行和本机客户端为主，同一应用中的内核统一维护仿真状态。接口保留独立的客户端、订阅与回合身份，支持多个客户端共享实例的设计。

首轮原型采用完整信息条件与简单规则或脚本策略。策略输入保持独立接口，有限观测、通信和记忆后续实现。

Python API 首先提供同步写法，异步写法沿用相同的回合与提交语义。查询注册、动态查询、定时命令和事件回调按具体 API 与验收案例分步接入。

## 原型参考策略

首轮采用实验策略、车辆基础策略与行人过街策略，使用统一观测、动作和行为切换接口。策略与实验代码优先使用 Python；Rust 提供 GUI 独立运行所需的基础参考策略，仿真内核与 GUI 继续采用 Rust。

Python 策略可以通过 API 接入 GUI 或 headless 实例。Rust 参考策略覆盖基础演示与运行验证，复杂行为与研究策略主要在 Python 中开发。各入口保持相同的状态、控制与记录语义，具体运行结果根据所选策略确定。

| 策略 | 功能范围 | 主要运行状态 |
| --- | --- | --- |
| 实验策略 | 按普通代码中的时间或状态判断提交动作，构造安全通过与接触案例 | 实验阶段及已执行操作的身份 |
| 车辆基础策略 | 使用参考路线、目标速度与完整信息，选择转向、减速和等待等基础动作 | 导航参考、路线进度及当前行为阶段 |
| 行人过街策略 | 表达等待、开始过街、继续与停止，根据环境变化更新动作 | 过街目标、当前阶段与相应逻辑时刻 |

路线采用、车道选择、重新规划和对其他主体的响应均由策略实现。原型使用配置明确、便于复查的规则，等待或阶段持续时间根据逻辑时间与实际事件计算。

接管期间持续维护 Agent 的通用记忆。交还控制时，参考策略读取当前状态、目标和历史，重新校验阶段与路线进度，按有效状态继续决策。更换策略按模型定义初始化私有状态。

原型参考策略用于验证接口、运动与闭环流程。其现实行为适用性需要单独校准与评价。具体规则与参数随案例验证确定。

## 首轮验收

1. 加载 OpenDRIVE 路段与交叉口，显示车辆及横穿行人。
2. 执行指定路线与预设动作，运行安全通过和发生接触的案例，查看状态与事件。
3. GUI 提供运行、暂停、单步、重置、平移缩放、主体选择和属性查看。
4. headless 模式可以加载场景并执行逻辑步；Python API 库可以连接已有实例或启动 GUI/headless 实例，再通过统一命令操作场景。
5. 相同配置与实际 Tick 命令的运行结果保持一致。

GUI 与 Python 采用共享控制。基础命令记录应保留实际生效 Tick、合并和覆盖结果，作为重跑依据。完整状态录制、检查点、结果回放和时间轴操作按阶段补充，语义见[执行与记录](execution.md)。

## 补充能力

参数编辑、二维与 2.5D 切换、有限观测、通信与记忆、事故清除、并行决策及更完整的重跑检查在首轮之后补充。

下表定义整个技术原型阶段的验收范围。

| 领域 | 验收要求 |
| --- | --- |
| 运行与画布 | 加载、运行、暂停、单步、重置，显示道路和主体，支持平移缩放、选择与属性检查 |
| 编辑与显示 | 暂停时编辑允许参数，按明确 Tick 生效；二维与 2.5D 使用同一世界数据 |
| 程序接口 | CLI 和 Python 加载场景、读取批量数据、执行命令与单步运行 |
| 入口一致性 | 相同配置与实际 Tick 命令产生一致的状态、动作和事件 |
| 地图 | 导入最小样例，检查道路几何、连接与源身份，明确支持范围 |
| 数值与违规 | 核验匀速、制动、连续运动、区间接触、路中横穿与车辆违规 |
| 事故恢复 | 事故主体停留、周边交通继续、显式清除后恢复通行 |
| 信息与并行 | 检查感知、通信来源与记忆隔离，比较顺序和并行的确定性结果 |
| 工程质量 | 评价冷构建、增量检查、启动、核心代码修改与桌面交互 |

训练、完整城市规模和复杂感知融合不属于首个运行窗口的验收条件。跨平台支持按实际构建和运行结果说明。对象规模、帧率与构建耗时在明确测试条件后报告。
