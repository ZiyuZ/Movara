# 路线图

本文定义阶段目标与验收范围，任务进度见[工程筹备计划](TODO.md)。

## 交付阶段

| 阶段 | 目标 | 交付内容 |
| --- | --- | --- |
| 工程筹备 | 明确设计边界与技术可行性 | 原型范围、模块职责、开发规范与技术验证方案 |
| 技术原型 | 验证工具链和基本运行流程 | Windows 桌面、CLI、同核 Python 调用与最小场景 |
| 核心能力 | 提供可重复的运动与实验基础 | 接触、控制、运行记录、恢复和干预分支 |
| V1 混合交通平台 | 提供可操作的独立平台 | 三类主体、路口信号、场景配置、保存加载与无界面实验 |
| 后续扩展 | 提升行为、规模和输出能力 | 模型校准、城市规模、局部 GPU、三维表现与传感器 |

技术原型、研究能力和平台版本分别验收。各能力可以按依赖并行发展，具体实施顺序由阶段范围确定。

## 技术原型

技术原型验证单机应用、仿真内核、GUI/headless 与 Python 的基本运行流程。场景范围、参考策略、首轮验收及补充能力集中在[技术原型方案](design/prototype.md)。

## 研究能力里程碑

M0–M3 表示平台面向干预、信息和学习实验的能力层次，Impact 是相关能力的使用方之一。

| 里程碑 | 能力 | 验收重点 |
| --- | --- | --- |
| M0 运动与分支 | 两车运动、轮廓接触、控制、共同历史分支与二维回放 | 安全通过、默认接触、有效制动和动作过晚仍接触 |
| M1 有限信息 | 世界与主体观测分离，表达遮挡、采样、误差和延迟 | 信息来源、采集与到达时间、决策因果关系 |
| M2 交互响应 | 接入经验证的车辆或行人响应模型 | 干预后的重新决策、闭环行为与适用范围 |
| M3 学习任务 | 标准观测与动作、奖励、终止和截断接口 | 信息边界、物理事实与任务条件、独立评价 |

M0 提供可重复场景、实际控制、状态、接触与完成记录，以及轨迹和控制时间图。分支首次干预前的状态应一致，并核验运动约束、步长敏感性和结果追溯。

学习型行人、视觉输入、CARLA 和训练不属于 M0 的必要条件。车人交互在 M2 中单独通过行人行为与闭环评价。

Movara 维护共同的运动、信息、事件、分支和回放。研究使用方维护研究问题、实验协议、指标和结论。平台验收与科学假设检验分别进行。

## V1 与后续扩展

V1 目标包括机动车、非机动车、行人、简单路口与信号、原生桌面、场景编辑与保存加载，以及 Python 无界面实验。参考策略可用于验收平台功能，行为真实性按独立评价确定。

后续工作包括已有模型与权重接入、行为风格、研究区与外围策略分层、城市规模和持续运行。自动区域切换需要定义历史和记忆衔接。

卫星影像底图与道路材质叠加、事故视频重建研究结果接入作为后续能力安排。地图、场景和主体接口支持导入与复核，视频重建算法在独立研究环境中维护。重建功能不纳入应用。范围见[地图与场景扩展](requirements.md#后续地图与场景扩展)。

外部策略与模型推理可以在后续评估多进程或跨机器分工，保持世界状态与逻辑时间的统一所有权。远程接入、任务分配和传输成本按对应规模验证，多机器计算不属于早期验收要求。

CPU 基线建立后，可以按完整阶段收益安排局部 GPU 验证。可选计算后端的采用条件见[开发指南](development.md#cpu-与局部-gpu-计算)。

完整时间轴、事故录制、驾驶设备、自由三维、CARLA、可替换视频生成和外部物理控制按用途逐项扩展。后续输出边界见[桌面界面设计](design/gui.md#后续画面与传感器输出)。
