# 工程筹备计划

本计划组织设计讨论、技术验证与工程筹备。平台交付阶段见[路线图](ROADMAP.md)。勾选表示已形成设计结论，具体能力按对应阶段验收。

当前议题：**运行控制与策略调用**。模块与接口的设计结论及文档组织完成本轮提交，后续按下列待办细化协议。

## 待推进事项

议题按下列顺序推进。需要产品选择的行为语义集中讨论；字段命名、符号和基础数据约定根据已确定原则直接维护，具体算法与参数通过验证确定。

### 模块与接口

- [x] 明确道路候选、位置归属、轮廓占用和导航匹配的区别。
- [x] 确定道路与车道纵横向坐标、查询参考点、搜索范围和结果语义。
- [x] 确定公开位姿与查询默认使用中心原点，模型内部参考点由内核转换。
- [x] 确定主体查询返回完整基础状态包装对象，按对象与范围筛选。
- [x] 明确路网提供查询与基础寻路，Agent 决定导航参考、车道和重新规划。
- [x] 明确轨迹采用主体中心、带时间的采样位姿，并通过运动输入执行。
- [x] 确认轨迹插值、可行性反馈、滚动替换及到期交还控制的基本语义。
- [x] 同时保留秒与 Tick，允许自定义固定逻辑步长，显示频率单独设置。
- [x] 确定按秒请求向不早于目标时刻的边界换算，记录实际 Tick，数值容差通过验证确定。
- [x] 确定 API 组织便捷请求，内核保存行为上下文、恢复计划及执行时刻。
- [x] 区分 API 本地状态、Agent 持续通用记忆及可切换行为模型的私有状态。
- [x] 确定多客户端共享同一世界与协调入口，早期单机，跨机器策略计算后续评估。
- [x] 确定实验、车辆基础和行人过街策略，说明导航、私有状态及接管衔接，策略与实验代码优先 Python。
- [x] 明确运动反馈的身份、时间版本、输入解析、实际状态、约束及轨迹偏差。
- [x] 完成模块与接口的设计审阅及文档整理，形成本轮提交范围。

成果：[核心接口](design/core.md#程序接口)、[主体设计](design/agents.md)、[运动与接触](design/motion.md)、[技术原型方案](design/prototype.md)。

### 运行控制与策略调用

- [ ] 明确主动单步与自动控制订阅的组合、返回数据和等待规则。
- [ ] 明确事件过滤、回调驱动、暂停期间的事件处理及取消确认。
- [ ] 补齐场景、录制与退出流程的关键 API，细化请求结果与异常分类。
- [ ] 明确查询注册与定时命令的修改、取消及生效边界。
- [ ] 细化应用启动、连接信息、就绪与退出确认的数据接口。
- [ ] 根据批量查询与控制流程选择本机通信、协议版本和数据传输方式。

成果：[执行与记录](design/execution.md)、[Python API](python-api/README.md)、[事件与回调](python-api/events.md)。

### 技术验证

- [ ] 确定地图、几何、桌面及 Python 连接的关键验证项目。
- [ ] 明确 Windows 验证步骤、采用条件与调整路径。
- [ ] 评价构建反馈、可维护性及分发成本。
- [ ] 通过运动与接触案例确定时间步、子步和数值容差。
- [ ] 为原型案例确定主体参数预设与运动反馈验收条件。
- [ ] 验证轨迹跟踪算法、参考插值及误差阈值。

成果：关键依赖与数值方案的验证结论。

### 工程创建

- [ ] 补齐统一构建、运行、格式检查和必要测试入口。
- [ ] 确认第一轮实现范围，形成可审查的小任务。

成果：工程组织与第一轮实施清单。实现与依赖安装按已确认范围安排。
