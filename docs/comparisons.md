# 同类工具对比

本文从应用场景、主体行为、信息条件和使用接口比较 Movara 与同类交通仿真工具。各工具按统一维度组织。

表中 Movara 的内容描述设计目标。功能与性能结论应结合对应版本、测试条件和运行结果解释。

## SUMO

SUMO 提供路网、交通需求、路线、信号和微观交通模型。Movara 的设计重点包括主体交互、有限信息、场景干预与原生桌面实验流程。

### 能力比较

| 领域 | SUMO | Movara 的设计方向 |
| --- | --- | --- |
| 路网与交通 | 地图转换、交通生成、路线分配与重规划 | 普通 OpenDRIVE 输入，入口生成规则与指定路线 |
| 主体行为 | 跟驰、换道、行人模型及个体参数 | 导航、行为、轨迹与控制分层，支持规则、脚本和学习策略 |
| 信息条件 | 随模型、接口和扩展配置确定 | 主体局部感知、消息来源、延迟与记忆显式表达 |
| 违规行为 | 通过行为参数和控制配置表达多种违规 | 合法性独立于运动执行，偏离车道后保持几何查询与接触能力 |
| 接触与事故 | 碰撞判据、事故处理与传送配置 | 对象轮廓与区间接触，事故占道、清障和持续运行 |
| 管理操作 | 信号程序、道路管理与外部控制 | 统一命令描述信号、流量、道路组织和主体干预 |
| 使用接口 | sumo-gui、TraCI 与 libsumo 等 | 原生桌面、CLI 和 Python 共用内核及命令语义 |
| 记录与分支 | 按所用接口和配置确定 | 实际命令、动作和事件记录，完整检查点与干预分支 |

逐主体建模和违规行为也是 SUMO 的已有能力。Movara 的价值需要结合具体任务、使用成本和实际交付评价。

### 适用场景

SUMO 是交通管理语义和正常交通行为的重要参照。已有交通需求、路由和信号工具可以为城市运行研究提供基础。

Movara 关注可检查的主体信息边界、可替换策略、干预后的闭环响应，以及桌面与程序调用的一致性。平台目标由[平台需求](requirements.md)定义，执行语义见[核心设计](design/core.md)。

已有工具或库的局部复用按功能、许可、适配和维护成本决定，具体原则见[开发指南](development.md#依赖选择)。

## 统一比较条件

同场景比较采用相同的源地图、交通输入、主体条件和管理操作，记录工具版本、参数、控制方式与实际执行结果。

场景包括正常路口交通、路中横穿、闯红灯、错误车道转向、违规停车、外部策略控制和事故恢复。评价同时覆盖场景表达、配置成本、行为响应、运动连续性和记录完整性。

性能比较明确对象规模、硬件、步长和运行时长，测量地图查询、决策、运动、接触、记录与显示的完整成本。比较结果按对应版本和测试条件解释。
