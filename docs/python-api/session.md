# 连接与会话

`Session` 表示到一个 Movara 应用实例的连接，封装场景、运行、查询和记录操作。连接已有应用和启动新应用返回相同的操作对象。

统一推进、消息驱动与事件处理见[API 运行模型](runtime.md)。本文定义连接入口、实例生命周期与运行操作。

## 关键入口

```python
def connect(
    endpoint,
    *,
    control=True,
    queries=None,
    timeout=None,
) -> Session: ...

def launch(
    executable=None,
    *,
    headless=False,
    control=True,
    queries=None,
    timeout=None,
) -> Session: ...
```

以上为关键签名方案。`queries` 是名称到查询描述的映射；查询类型见[数据与控制](data-and-control.md)。

| 参数 | 语义 |
| --- | --- |
| `endpoint` | 明确定位已有应用的连接信息，具体表示随通信接口确定 |
| `executable` | 应用程序路径，省略时按系统 PATH 定位 |
| `headless` | 新应用的启动模式，默认 GUI，设为真时使用无界面模式 |
| `control` | 建立控制或观察模式的连接，默认控制模式 |
| `queries` | 随连接登记的预定义查询，按名称批量返回结果 |
| `timeout` | 连接或启动等待超时；省略时采用有界的默认设置 |

应用定位、启动、就绪检查与连接失败返回具体异常。启动等待超时与控制回合超时分别配置，后者属于运行协议。

### 就绪与连接确认

`launch` 等待应用完成初始化，并取得该实例的连接信息后再建立会话。应用通过启动方指定的就绪回报通道返回实例身份与 endpoint，具体通道随本机通信方案确定。GUI 模式的就绪回报独立于控制台显示。

| 确认内容 | 用途 |
| --- | --- |
| 应用实例身份与 endpoint | 确认实际连接的应用，区分并存实例 |
| 协议版本 | 检查应用与 API 的通信约定，版本不匹配明确报错 |
| 连接身份 | 关联该连接的请求、订阅和诊断来源 |
| 当前运行身份与状态 | 区分未加载、暂停、运行、结束和故障停止 |
| 当前 Tick、状态版本与步长 | 建立时间和查询上下文，未加载时按状态表达 |
| 订阅与查询确认 | 返回注册身份、版本及初始生效边界 |

连接就绪表示可以接收领域操作，场景通过加载操作建立。调用方可以连接已经在运行的应用，初始确认采用相应逻辑边界的状态。连接与启动失败保留已知实例及阶段信息。

## 自动订阅

`control=True` 时，连接建立过程同时登记同步控制订阅。返回的 `Session` 已具有接收控制回合的能力，`session.frames()` 读取该订阅的帧。

`control=False` 时，连接初始登记观察订阅，Python 通过 `session.updates()` 接收批量数据。观察订阅自身保持非阻塞，其他 GUI/API 命令继续遵循共享控制规则。后续可以独立登记必需事件控制回调，只在匹配事件时等待提交。

观察连接也可以显式请求暂停、修改或单步，操作按系统状态执行；观察订阅自身保持非阻塞。精确的逐 Tick 决策使用控制模式。

连接的推进义务由其已有订阅共同决定。事件控制与逐 Tick 控制可以并存，通过同一驱动流程按阶段处理，详见[事件与回调](events.md)。

初始查询与订阅在确认生效边界后返回，避免连接刚返回时漏掉本应等待的首个控制回合。实际 Tick 与注册身份由应用确认。

## 场景与运行

| 操作 | 语义 |
| --- | --- |
| `session.load_scene(path)` | 验证并加载场景，建立新的运行上下文 |
| `session.save_scene(path)` | 保存明确的场景配置 |
| `session.reset()` | 按场景初始条件建立新运行 |
| `session.run()` | 请求连续运行，控制订阅继续参与推进条件 |
| `session.pause()` | 请求在逻辑边界暂停 |
| `session.step(...)` | 在暂停状态执行主动单步实验 |
| `session.terminate()` | 结束当前运行，保留最终状态与原因 |
| `session.start_recording(path, ...)` | 从确认边界开始录制，返回记录身份与起始版本 |
| `session.stop_recording()` | 结束当前录制并确认最终边界及输出结果 |
| `session.save_checkpoint(path)` | 保存允许边界上的完整运行上下文 |
| `session.restore_checkpoint(path)` | 在允许状态恢复上下文，建立可辨识的恢复运行身份 |

加载、重置和单步遵循[系统命令状态约束](../design/execution.md#系统运行命令)。场景文件格式、配置对象和返回类型由场景接口细化。

`save_scene` 保存场景定义，运行中的主体运动与临时接管属于运行状态。将当前状态建立为新场景需要显式转换，恢复完整运行使用检查点。各数据对象的范围见[场景与运行上下文](../design/core.md#场景与运行上下文)。

录制和检查点方法表示相应阶段的接口方向，首轮交付范围见[技术原型方案](../design/prototype.md)。检查点的完整性需要覆盖内核状态与调度上下文，外部策略按自己声明的恢复能力接入。恢复后校验旧请求与身份，内部队列按明确的身份映射规则重建。

## 连接与应用生命周期

`session.close()` 正常断开连接并保留应用。`session.shutdown()` 明确请求应用结束运行并退出。两者都可以用于已有应用或 API 启动的应用，操作对象保持一致。

`Session` 支持上下文管理。正常离开上下文执行 `close()`，应用退出通过 `shutdown()` 明确发起。连接记录实例创建来源，供日志与诊断使用。

存在未完成控制回合时，应先完成提交或明确结束相应运行。断开连接不得隐式提交空动作，未完成回合按控制失败规则处理。

连接关闭前完成的控制回合可以通过明确的订阅结束流程退出。控制订阅结束、生效边界及确认信息由会话协议规定，API 在关闭过程中落实这一规则。

正常关闭时，应用确认注销该连接的新控制参与，既有回合先完成或按显式终止规则取消。关闭结果包含已确认边界，随后释放连接及本地回调资源。其他连接收到共享运行变化时更新自己的状态。

`shutdown` 先取得应用退出确认，随后将对应的连接关闭视为预期结束。退出前应用交付最终状态和未完成请求的取消说明。意外失去连接按连接错误报告，必需控制方的失败沿用运行故障规则。

## 同步与异步

同步接口阻塞等待请求结果或帧通知。异步接口提供对应的等待与迭代形式，使用独立的异步会话类型表达，具体入口名称在异步接口细化时确定。

两种形式共享模式选择、查询注册、回合完成和错误规则。异步等待期间，应用仍保持必需提交的推进条件。
