# 数据与控制

Python API 采用显式查询、批量提交和带时间版本的数据。接口对象描述通信边界，查询结果支持普通的本地读取。

## 基本对象

| 对象 | 职责 | 主要内容 |
| --- | --- | --- |
| `Session` | 应用连接与仿真操作 | 实例身份、运行状态与请求入口 |
| `Query` | 在本地构造查询描述 | 对象选择、空间条件与信息范围 |
| `Snapshot` | 表达一批查询结果 | 运行身份、Tick、状态版本、命名数据与事件 |
| `QueryResult` | 表达单项查询结果，可直接遍历状态对象 | 结果集合及所属时刻与版本 |
| `ObjectState` | 表达某个版本的主体基础状态 | 身份、Transform、尺寸、轮廓、运动与生命周期 |
| `Frame` | 表达一个待完成的控制回合 | 回合身份、固定版本数据、查询与提交入口 |
| `Registration` | 管理查询与事件订阅 | 注册身份、名称、版本、生效边界与取消操作 |
| `Event` | 表达已经发生的仿真事实 | 事件类型、身份、参与对象、时刻与状态版本 |
| `EventContext` | 表达待完成事件控制的上下文 | 事件批次、固定版本数据与查询能力 |

查询结果按预定义名称组织，例如 `frame.data['vehicles']`。主体查询返回一组本地只读 `ObjectState`，位置、速度和加速度等数值使用统一坐标系与单位。

具体数组和记录类型按数据接口定义。批量数据应适合遍历、筛选和后续数值处理，类型转换保持显式。

### 基础状态包装对象

`ObjectState` 提供 `id`、类别、`transform`、`dimensions`、`outline`、速度、加速度、角速度与生命周期等基础数据。`Transform` 表达主体中心原点的位置与朝向，轮廓明确自己的局部坐标与相对变换。

首轮采用完整基础状态对象，调用方按需读取属性。只关心坐标时直接读取 `obj.transform.position`。字段投影、按列传输等优化在出现实际性能需求后评估。

属性读取保持本地执行。世界轮廓等派生结果可以根据已收到的数据本地计算，额外地图关系、路线、观测历史和策略状态通过显式查询取得。包装对象与版本关联，后续读取保留该版本的值。

## 查询描述与本地读取

`Query` 是声明所需数据的值对象，构造和组合发生在 Python 本地。执行、注册与动态查询通过明确的方法调用发起。

查询可以选择对象身份、主体类别和空间范围，例如指定对象周围一定距离内的主体。世界真值、Agent 观测、地图和事件分别定义信息范围，策略输入遵循主体观测边界。

`frame.data` 和 `snapshot.data` 表示已经收到的数据。读取、遍历和筛选这些数据保持本地访问，数据自身保留所属的运行、Tick 和状态版本。

修改世界通过动作或命令提交，本地数据操作只作用于本地结果。

## 实体身份与主体数据

世界中的对象以实体 ID 标识。Agent 是实体参与决策与控制的能力，Python 接口中的 `agent_id` 沿用实体身份。查询可以按对象类别筛选车辆、非机动车、行人或障碍物。

主体基础状态按统一包装对象提供。目标、路线、运动参数、策略配置及允许的观测通过相应的显式查询取得。动作能力按主体的运动配置校验。

实体 ID 在同次运行内保持稳定且不复用。保存对象引用时需要同时保留运行身份，重置或加载场景后的请求按新的运行身份校验。查询结果是对应版本的数据，后续读取保留该版本的值。

世界真值查询用于场景操作、实验控制与评价。Agent 信息查询返回该主体允许使用的观测与记忆。两类结果具有明确的信息范围，策略输入按实验配置选择。

观测结果按允许的信息定义自己的记录，未知值、估计来源与时刻保持显式。完整基础状态对象用于世界真值查询，Agent 感知结果遵循相应信息边界。

主体操作及其道路关系见[主体设计](../design/agents.md)，Rust 状态所有权见[核心设计](../design/core.md#rust-数据与访问边界)。具体查询字段、动作类型与主体编辑操作按领域接口逐项定义。

道路关系查询支持车道候选、参考曲线上的纵向位置、横向偏移、航向差以及主体轮廓占用。结果标明参考曲线与地图版本，并表达空匹配和歧义。预定义查询和动态查询共用这些字段的语义。

## 查询执行与注册

```python
class Session:
    def query(self, query: Query) -> QueryResult: ...
    def register_query(self, name: str, query: Query) -> Registration: ...

class Frame:
    def query(self, query: Query) -> QueryResult: ...
```

`session.query(...)` 查询明确的已提交状态，返回对应版本。`frame.query(...)` 查询当前控制回合固定的状态版本，查询期间应用保持推进等待。

预定义查询由 `connect/launch` 的 `queries` 参数登记，也可以在运行期间通过 `register_query` 增加。应用按已有控制或观察订阅的边界批量交付结果。

`session.queries` 提供按名称访问的查询注册对象，包含连接时登记的查询。该映射由已确认的注册信息维护。`registration.update(query)` 修改规则，`registration.cancel()` 明确请求取消。

注册、修改和取消返回确认的规则版本与生效边界。预定义的是规则，结果随世界状态更新；动态查询用于按需补充数据。

查询完成保持控制回合未提交状态。查询注册的取消也按自己的生命周期处理。回合最终通过提交确认完成。

### 注册变更边界

每次注册变更携带注册身份和预期版本，确认结果给出生效批次或边界及新版本。已经固定的查询批次继续使用原规则，后续批次使用确认后的规则。暂停时可以处理注册变更，生效确认通过状态版本或交付批次表达。

取消从确认的边界起停止产生新交付，已经形成的回合和结果保持有效。当前控制回合的提交义务继续履行。API 保留完成既有交付所需的本地对象，处理完相应回合后释放。

查询与事件订阅归连接管理。查询描述只引用类别或区域等可复用条件时，可以跨重置继续登记；显式引用旧运行实体的注册在重置或加载时失效，并交付原因。逐 Tick 控制订阅继续归原连接，新回合使用新的运行身份。

## 接收控制回合

```python
class Session:
    def frames(self) -> Iterator[Frame]: ...

class Frame:
    def submit(self, *, actions=(), commands=()) -> SubmissionResult: ...
```

`frames()` 消费连接时已经建立的控制订阅。观察模式通过 `session.updates()` 取得 `Snapshot`，沿用非阻塞推进规则。

应用形成控制回合后，发送查询结果并等待有效提交。Python 可以读取预定义结果、发起动态查询、判断条件和计算动作，最后一次提交本回合的动作与命令。

空批次表示没有新增干预，主体已有策略和明确的持续动作仍按各自定义执行。失败或缺失的控制提交触发故障停止。

## 动作、命令与结果

`Action` 描述主体的运动输入或计划，保留主体身份、单位和执行区间。`Command` 描述世界修改、事件与系统操作。构造动作和命令数据保持本地执行，提交时批量传输。

关键动作可以提供清楚的构造方式，例如 `Action.acceleration(agent_id, value)`；系统暂停可由 `Command.pause()` 描述。完整动作与命令集合随领域接口设计细化。

加速度数值采用 `m/s²`。上述简单动作作用于当前控制区间，持续动作与轨迹通过明确的区间描述表达。

临时接管保留 Agent 的默认行为模型，到期或显式结束后交还控制。行为模型变更修改默认配置，后续持续生效。两类操作通过相同的提交入口处理，状态衔接见[默认行为与临时接管](../design/agents.md#默认行为与临时接管)。

`Trajectory` 描述带相对时间的主体中心 Transform 序列，可以携带目标速度。轨迹和直接控制通过同一个批量提交入口进入内核，接收后返回轨迹身份、实际生效边界和校验结果。参考计划、实际执行状态及到期规则见[轨迹接口与执行](../design/motion.md#轨迹接口与执行)。

轨迹对象在本地构造，读取实际位置使用查询结果。轨迹接受后由内核执行已有计划，滚动更新通过新的完整轨迹替换，提交时机由 Agent 或外部控制循环决定。

提交关联运行、Tick 和回合身份，应用按[命令规则](../design/execution.md#主体命令解析)处理合并、覆盖、警告和错误。接收回执与最终执行结果分别表达，结果应能追溯相关命令。

回合中的动作作用于本次执行区间，普通世界修改进入后续普通命令窗口。创建等操作的执行结果返回实际身份和版本，后续请求使用已经确认的实体身份。结果结构与领域事件见[请求、结果与领域事件](../design/execution.md#请求结果与领域事件)。

在控制回合中提交暂停命令时，应用确认当前提交后，在逻辑边界停止后续自动推进。已经确认的暂停作为后续调度约束，便于循环有序结束。

同一回合支持一次有效提交。迟到、重复或身份不匹配的提交明确报错。已取得的数据保留版本，后续动态查询按有效回合和历史数据支持范围处理。

### 请求结果与错误

| 调用类别 | 直接返回内容 | 后续结果 |
| --- | --- | --- |
| 普通查询 | 对应已提交版本的查询结果 | 结果对象保持本地读取 |
| 立即可处理的修改 | 实际执行结果或错误，包含版本与必要身份 | 相关事件随订阅交付 |
| 未来边界的命令 | 命令身份、目标边界及接收回执 | 实际执行后交付结果 |
| `frame.submit` | 当前回合提交的接收结果 | 世界推进后取得动作结果与反馈 |
| `step` | 本步完成及事件处理后的结果、快照与反馈 | 后续推进由新的请求决定 |

请求在接收、排队和完成阶段分别保留身份及状态。接收回执说明输入已经登记，执行结果说明实际处理事实。普通批次沿用逐项处理规则，原子修改组按完整性约定接收。

| 错误类别 | 内容与处理 |
| --- | --- |
| 输入或能力错误 | 无效参数、不支持的查询或动作；指出字段与支持范围 |
| 对象或版本错误 | 对象不存在、运行已变更、注册版本失效；返回相关身份 |
| 调用状态错误 | 连续运行中单步、持有 Frame 时递归推进、非法驱动重入 |
| 连接或请求超时 | 返回请求身份、已知阶段及结果是否确定 |
| 运行失败 | 计算失败或必需控制方失败；保留运行状态与诊断 |
| 生命周期取消 | 重置、终止或退出取消操作；返回确认原因与最终边界 |

Python 异常与 Rust 错误使用可对应的类别和上下文字段，具体类型随代码实现确定。输入失败与世界运行故障分别报告。

请求超时只说明等待超过墙钟期限，已接收命令可能仍在队列中或已经执行。结果尚未确定时明确返回该状态，调用方可以按原请求身份查询结果。超时不自动撤销或重复发送操作。

持有待提交 Frame 时，普通查询按相应上下文执行。需要等待该 Frame 完成的同步操作返回调用状态错误，暂停等操作可以加入当前批次提交，终止与退出沿用取消回合的生命周期语义。

## 定时命令与事件处理

已知时刻的操作通过普通命令指定目标 Tick 后提前提交，内核在对应边界执行。命令内容采用已有的领域操作，固定行为采用明确的场景选项。

尚未进入固定输入窗口的定时命令可以按身份修改或取消，返回新版本和确认结果。修改后的目标时刻仍需有效。已经进入执行窗口的请求返回已执行或无法取消的明确结果，历史效果保持原有事实。

定时命令归当前运行，重置、加载或终止使对应的待执行命令失效并返回原因。正常断开提交方后，已被应用接受的定时命令仍按原计划处理。需要撤销时显式取消。

自定义事件处理通过 Python 回调完成，复杂条件也可以直接在逐 Tick 控制回合中判断。查询和事件订阅提供身份、更新、取消及生效确认。

触发来源、Tick、命令序号与实际处理结果进入运行记录。

`frame.events` 与 `snapshot.events` 提供本次交付的事件集合，也可以登记 Python 控制或观察回调。定时命令、内置选项与 Python 回调的执行位置、通信与控制关系见[事件与回调](events.md)。

## 失败与共享控制

GUI 和 Python 共享操作能力，应用始终统一调度。控制等待期间，GUI 保持显示、查询和请求接收，已发送的回合数据保持原版本。

Python 在控制回合中发生未处理异常时，API 库应尽力报告失败。应用收到失败报告、发现控制连接断开或等待提交超时后，停止该次仿真并标记失败，保留状态和诊断信息。

普通观察连接的丢失按连接错误处理。控制回合的提交义务、生效窗口及故障恢复约束见[执行与记录](../design/execution.md)。
