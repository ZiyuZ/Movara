# 平台需求

Movara 面向城市交通管理与多主体交互研究，提供独立仿真内核、原生桌面界面和 Python 接口。本文定义平台的目标能力与范围。阶段交付见[路线图](ROADMAP.md)。

## 应用场景

平台覆盖机动车、非机动车和行人在道路网络中的持续运行，支持正常交通、违规行为、冲突与事故处置。交通参与者根据各自可用的信息作出决策，管理者可以调整交通组织、发布信息和处置事件。

研究者可以控制场景、策略和信息条件，从共同历史建立不同干预分支，分析后续行为与交通结果。真实数据用于模型校准和评价，仿真提供可重复的实验条件。

城市规模路网属于长期目标。初始原型采用一个路段和一个交叉口，包含车辆、行人及路中违规横穿。城市规模能力需要单独验收。

## 地图与交通环境

首轮优先接入普通 OpenDRIVE `.xodr` 文件，地图制作使用外部工具。地图接入包括结构读取、道路几何、车道连接、路口拓扑、信号关联和空间查询。导入格式与运行时地图分别组织，具体职责见[路网与空间模型](design/network.md)。

混合交通需要表达车道、人行道、过街区域、等待区域和共享空间。场景可以为源地图补充实验区域与交通语义。补充配置应保留与源地图的关联。

交通通过入口生成规则和指定路线组织。主体的到达、实际进入、通行和离开分别记录，入口积压应具有明确状态。持续运行还包括事故占道、清障和交通恢复。

## 交通主体与行为

车辆、非机动车和行人采用统一的 Agent 基本协议，导航、行为和运动模型按主体类型分别实现。Agent 在本文中指具有身份、观测、决策状态和动作输出的交通主体。

运动模型服务交通管理与主体交互，机动车采用简单且明确的运动学与能力约束。非机动车与行人的通行方式、行为差异和交互响应按交通场景细化。各主体初始化时明确速度、加减速和适用的转向能力范围。

行为分为目标与导航、行为决策、短时轨迹规划和运动控制。平台提供轨迹与控制两类动作接口，规则、脚本、学习策略和人工输入通过统一边界接入。

研究主体以可复用的小型行为模型为主要方向。规则策略用于基线、工具验证和低成本外围交通。激进、正常和保守表达行为风格预设，具体模型与参数根据评价结果确定。

行人决策需要表达等待、起步和过街过程。车辆动作变化后，交互主体应根据新状态重新决策。闭环响应、轨迹预测和固定轨迹重放分别评价。数据与模型要求见[行为模型](design/models.md)。

## 世界状态与违规行为

对象的位置、姿态、运动和轮廓构成世界的几何基础。车道关联用于导航和规则判断，允许缺失或存在多个候选。

车辆与行人的运动保持连续，运动执行遵循明确的数值和运动学约束。闯红灯、违规停车、逆行、错误车道转向和行人自由过街属于可表达行为。违规对象照常参与观测、空间查询与接触检测。

交通合法性与几何可执行性分别判断。底层执行不得通过自动吸附、无记录传送或隐含的全知避碰改写过程。额外安全控制应明确来源，并记录实际干预。

接触依据对象轮廓和运动区间判断。事故后世界可以继续运行，事故主体占据空间，其他主体按观测和策略等待、绕行或改道。任务可以配置暂停或终止条件。

## 感知、通信与记忆

策略输入由每个 Agent 的允许信息生成，支持视域、遮挡、采样周期、误差和消息延迟。信息保存来源、观测时刻、接收时刻和有效性。

通信包括发送方自身状态广播，以及发送方感知目标共享。两类能力可以分别配置或组合。主体的本地感知、通信、策略、控制权限和行为风格分别配置。

记忆保留历史观测、目标估计、有效期和必要的模型状态。被遮挡对象的估计根据已有信息更新。隐藏对象的当前世界真值不得用于刷新局部记忆。

主要决策输入采用二维结构化对象、矢量地图和历史信息。模型可以按需使用局部鸟瞰栅格（BEV）。场景渲染和相机感知不属于基本决策流程。

## 交通管理与场景干预

| 领域 | 目标能力 |
| --- | --- |
| 运行监测 | 对象状态、流量、速度、队列、延误、违规和事故状态 |
| 交通生成 | 入口流率、主体组成、路线分配和分时变化 |
| 信号控制 | 相位、时长、配时方案、优先通行和行人请求 |
| 道路组织 | 限速、封路、车道关闭、转向限制和分流 |
| 信息发布 | 拥堵、事故、施工、绕行和危险提示 |
| 网联设施 | 设备部署、覆盖范围、共享类别和更新频率 |
| 事故处置 | 现场隔离、救援派遣、拖离、清障和恢复 |
| 主体干预 | 临时接管、目标与路线修改、策略与信息条件切换 |
| 实验控制 | 运行、暂停、单步、重置、记录、回放、检查点和分支 |

管理措施、主体响应和直接世界编辑分别记录。交通标志改变通行规则，实体路障改变空间占用。信息发布后，主体可以延迟响应、忽略提示或违规。

管理者可以使用路侧感知、检测器、车端上报和历史统计。世界真值视图用于调试和明确的理想信息对照。上述能力按阶段交付，初始原型范围由路线图确定。

## 桌面与程序接口

原生桌面提供场景加载、运行控制、画布操作、属性查看和配置编辑。初期显示采用二维与简单 2.5D 视图。

同一个可执行文件提供 GUI 和 headless 两种启动模式，默认进入 GUI。CLI 在 headless 模式下提供无界面运行和导出。Python API 库可以连接已有应用，或自动启动 GUI/headless 应用，提供场景操作、批量观测、策略接入与单步实验。各入口采用相同的内核、场景配置和命令语义，同一实例中的世界保持唯一推进者。

GUI 和 Python 共享运行控制与世界修改能力。同一 Tick 可以处理多条命令，独立字段合并，冲突字段采用明确规则选出有效值。系统运行命令按状态与操作语义独立处理，具体规则见[执行与记录](design/execution.md)。

Python API 同时设计同步与异步编程形式，支持批量动作、观察通知和同步控制回合。同步控制订阅要求应用等待有效提交后继续推进，控制失败应报错停止该次仿真。

数据访问支持可动态注册和取消的预定义查询，以及按需动态查询。明确的条件与动作可以预注册到应用，Python 自定义条件通过控制回合处理。

平台以 Windows 原生环境作为优先验收平台，保留跨平台目标。支持情况以各平台的实际构建和运行结果说明。

## 记录与质量要求

场景配置、实际命令、动作、状态和事件支持结果追溯。检查点包含世界、逻辑时间、策略记忆、随机状态和在途消息。干预分支在首次干预前应具有一致的历史。

仿真录制覆盖初始条件、输入来源、命令顺序与解析结果，以及实际动作、状态和事件。结果回放展示已记录过程，重新仿真使用记录中的输入与时刻，新增干预建立实验分支。

数值运动、行为真实性和研究结论分别验证。数值验证包括匀速、制动、连续运动、接触时刻、步长敏感性和运行重复性。行为评价包括等待、让行、响应、通过、停滞和分布变化。

构建反馈、代码可维护性、桌面交互和分发成本属于工程质量要求。性能结论需要明确场景、硬件、版本、步长和测量范围。

## 后续地图与场景扩展

卫星影像可作为后续视图底图，在其上叠加由路网几何生成的道路表面、标线与道路材质。影像与地图保留坐标对齐关系，视图支持独立控制底图和道路图层。空间查询、通行关系和接触判断依据运行时地图，底图负责地理环境的视觉参照。该能力按后续阶段安排。

事故视频重建属于独立研究工作，研究流程产出可供 Movara 加载与检查的事故场景。重建结果可包含局部地面与路网、障碍、信号条件、主体初始状态和带时间轨迹，并保留空间尺度、坐标与时间映射、来源及不确定性信息。平台通过地图构建与场景装载、主体与轨迹操作、运行记录和实验接口接入研究结果。

场景复原用于检查记录中的过程，干预实验基于恢复条件运行主体响应。视频分析与重建算法在独立研究环境中维护。重建功能不纳入应用，应用提供适合导入、复核和实验的接口。相关能力在后续阶段细化，首轮交付范围保持既定安排。

## 范围边界

核心采用交通运动学与几何接触描述。车辆动力学、材料损伤和车身变形不属于核心范围。事故处置采用交通层抽象。

道路编辑器、完整城市出行需求分配、公交铁路业务、排放和充电模型不属于初始交付范围。

模型训练位于独立研究环境。内核不提供自动微分或训练系统。相机、真实感渲染、完整三维、驾驶设备和外部物理控制作为后续扩展单独设计。
